# Protocol

These rules make a number from this benchmark comparable to any other number from it. A result that
breaks one of them may still be interesting. Report it as **non-standard** and name the rule it
breaks.

## 1. What a method may use

| allowed | not allowed |
|---|---|
| `train` (+ `phase1`) to fit; `val` and `val_ood` to select models, tune hyperparameters and stop early | any test or hidden split for fitting, selection or tuning, including "just one look" |
| the `context` given to `fit`: dt, sensors, x_std, y_std, x_mean, IC box, input box, the nominal noise description, and **the modeller's model of the knowledge level** (`context["model"]`, NOMINAL parameters; `f_known` at `partial` / `realistic`) | the real plant's parameters (`mismatch30_params` in the metadata files), the plant code with `perturb`, the true `f` at `partial` / `realistic`, and any other metadata outside `context` |
| u_0..u_k and y_0..y_k at step k | future samples, the episode's family or signal parameters, `x`, `x0` |
| a prior (mean, std) that is the same for every episode of a split; the harness passes the centre of the IC box | per-episode priors built from test data |

**Model-free vs model-based.** A method that uses `context["model"]` is model-based and must use
the model of the knowledge level being scored. A model-free method gives the same result at `exact`
and `partial`, because they share their data. Report it once, flagged *model-free*.

## 2. Equal-data rule

Every compared method is trained on the same episodes: the same `train` split (or the same nested
subset `load(..., n=, seed=)`), plus `val` for selection. A method that adds data must give the
comparator the same data. This includes extra simulated episodes, other knowledge levels,
`phase1`, or event-structured augmentation. If it cannot, it reports the unequal-data number
separately as *unequal data* (PITFALLS P6). Data generated by the method's own model
(e.g. collocation states of the nominal model) is part of the method, not of the data. Report it.

## 3. Reference filters: tuning and gating

- The reference model-based filter is the **gated EKF** (`baselines.EKF(gate=True)`): chi-square
  innovation gate at p = 0.999 on the NIS, with forced acceptance after 5 consecutive rejections.
  This is the published rule of the research gating study. Stale samples (exact repeats) are skipped.
  No fixed safeguard against lock-out dominated (PITFALLS P12), so `ekf_huber`, a Huber filter
  without a gate, is reported next to it.
  Nominal Q = (0.005 x_std)^2 dt, R = (0.03 y_std)^2, P0 = (IC box width / sqrt 12)^2. It is fixed
  a priori and needs no tuning. An ungated filter is not a valid reference under outliers
  (PITFALLS P2).
- A learned observer facing the `outliers` condition may use an equivalent fixed rule fitted on
  `val`, for example a Huber clip of the output residual at k x 1.4826 MAD with k chosen on clean `val`.
  Report the rule.
- Tuning (Q/R inflation, learning rates, widths) is allowed only on `val` / `val_ood`. Every
  method gets a stated budget, and the budget is reported (number of configurations tried).
- Grey-box / UDE comparators must be trained the way they are deployed: the residual is learned
  through the same integrator (RK4, zero-order hold) the filter uses (PITFALLS P1).

## 4. Inclusion rule for plants

A plant enters the benchmark only if `hyperkkl-bench check-plant` passes all of these:

- interface: shapes and finiteness;
- observable: Gramian full rank at 90 % of the probe points, and a CRB proxy on the unmeasured
  states below 1;
- bounded: S(5T) <= 2 S(T), and the spread at the end <= 2x the spread early, under all four input regimes;
- design gate: the latent filter is well posed.

The frozen plants passed the full version (`experiments/cartpole_bounded/INCLUSION.md`).
`legacy_cartpole` failed boundedness and is excluded. The roles (dev / test) are fixed. Design
decisions use only the dev plants. A paper reports the test plants once, with a frozen recipe.

## 5. Seeds, uncertainty and reporting

- The unit of replication is the **training seed**. Report the mean over at least 3 seeds (5 for a
  headline claim) of the per-seed mean over test episodes, with a Student-t 95 % interval over
  seeds. Comparisons are **paired**: same seeds, same episodes, ratio per seed. Use Holm
  correction across cells.
- The episode-bootstrap CI in `Report.table()` measures episode variability for one fitted model
  only. It is not a substitute for seeds.
- Report every cell you ran, including losses. Report the divergence rate next to the NRMSE.
  Diverged episodes count with the clipped error (100).
- Report cost from `Report.cost`: latency on stated hardware, batch 1, 1 thread.
- Always quote `bench_version`, `data_version` and `scorer_version`.

```
# <study>: pre-registration       written <date, time, timezone> BEFORE any test-tier evaluation
Question:          <one sentence>

Cells:             <plants x knowledge levels x tracks>; dev / test roles respected: yes/no

Selection:         split(s) used for selection: val / val_ood; tuning budget per method: <k configs>
Seeds:             <list>; uncertainty: t-interval over seeds; paired comparisons; Holm over <family>

Deviations:        appended below with timestamps; the text above is never edited
```

## 7. Hidden test (leaderboard)

Submissions contain only the estimates for `hidden_*` (`hkb.hidden.predict`), the
`SUBMISSION.json` manifest, and a statement that §1 to §5 were followed. The host scores them with
the private labels. Hidden numbers are reported **next to** the public test numbers, never instead
of them.

## 8. Version 2.0: two families of state estimation

Sections 1-7 above still hold. v2 adds the family rules (section 0), the recipe rule (2a), the inclusion check for family A (4a),
and the reporting of the operating-profile tiers (5a).

### 8.0 Families and headline tiers
* A result names its cell as `family/plant/level` (for example `driven/battery/realistic`).
* **Family B (driven)**: the headline is the settled unmeasured NRMSE on `test_op_ood` / clean, reported next to
  `test_op_id`. The legacy tiers are reported in a separate table and never replace the operating-profile tiers.
  Input-record conditions (`input_realistic`, `input_cmd_vs_applied`, `input_quant`) change only what the estimator
  is told about u. The plant always received the applied input.
* **Family A (autonomous)**: the headline is `test_id` / clean. `test_ic_ood` is reported on both the settled and the
  transient window (the initial condition matters only before the attractor is reached), and `test_param_shift`
  separately. **There is no input-OOD tier in family A**, so no claim about generalisation to new inputs may cite it.
* An input-conditioned method (decoder conditioned on the input history, latent injection) evaluated in family A is
  an autonomous observer there. A family-A result cannot support a claim that input conditioning helps.

### 8.1 What a method may use
As v1. In addition: the operator names, profile seeds and the `cmd` column of the profile tiers are scoring
metadata. An estimator must not read them, except that `input_cmd_vs_applied` passes `cmd` AS the input. A method
may know the input box and actuator description of its plant (metadata `input`), as a modeller would.

### 8.2 Equal-data rule
As v1. **2a. Recipes.** Every split comes in a standard and an event-structured part. The reference recipe is
`mixed` = standard + event (1200 train / 128 val episodes). Compared methods use the same recipe. A method reported on
`standard` must report its comparators on `standard` too.

### 8.3 Reference filters, tuning and gating
As v1: the gated EKF is the reference yardstick, and tuning uses validation splits only, with the number of
configurations reported. v2 study budgets: tuned filters 8 (Q x {1, 3, 10, 30}, R x {1, 3}), grey-box / NODE / GRU 4
learning rates x 3000 steps, KKL peers 2 learning rates x 15000 steps at the HyperKKL parameter total, HyperKKL 2
phase-2 learning rates.

### 8.4 Inclusion rules
As v1 for every plant, plus **4a (family A): non-trivial unforced dynamics**. At u = 0, 64 ICs of the box, 5 T: in
the last 20 % of the run the median (over ICs) time-std of the most active state is at least 5 % of its reference
scale (std of |x_j| over the last 80 % of the run), at least 90 % of the ICs keep a late time-std above 5 % of the
largest reference scale, and the late / early (20-40 %) ratio is at least 0.5 (exact definition:
`hyperkkl_bench.autonomy`; `hyperkkl-bench check-autonomous --perturb 0` or `0,0.3`). Both must hold for the data plant of every
level offered.

### 8.5 Seeds, uncertainty and reporting
As v1 (at least 3 training seeds, 5 for a headline claim; paired per-seed ratios with t-intervals; Holm across
cells). **5a.** Report the op_ood / op_id ratio of every method. For profile plants with an uncited operator (card
field `uncited`), report that the profile is a benchmark choice.

### 8.6 Pre-registration template
As v1, plus a line `Family / tiers:` naming the headline tier per family.
